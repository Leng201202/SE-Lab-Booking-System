## Reflection

**Nay Win Aung · 6631503080 · AI Lead · Team FLUX**

### 1. Lessons learned: building with AI

As AI Lead, my job was to explain where AI helped us and to make sure we did not overclaim. AI touched every phase: Claude drafted proposal updates, diagrams, React code, SQL migrations and pgTAP tests. **What got better:** we turned AI use into rules, not habits. `CLAUDE.md` and `agent.md` told every agent that the database is the security boundary and that research must never be invented. We also made a read-only `diagram-checker` agent that can report mismatches but cannot edit. AI became a controlled tool with traceable output: 7 of 65 commits carry a `Co-Authored-By: Claude` trailer.

**What got worse:** measuring AI honestly was hard. A commit trailer shows disclosure, not how much code AI wrote or whether it saved time. We could not prove time saved, so we wrote "Not measured". When the local Supabase stack would not start, our 147 database assertions were _defined_ but not re-proven. AI also made it easy to produce confident documents faster than we could verify them, so review became the bottleneck.

### 2. Where I stand in the AI era

Many people can now generate code, so knowing how to prompt is not enough. I can use AI tools productively and, more importantly, I can design guardrails around them: data rules, review steps and honest disclosure. I still need deeper engineering skills so I can judge AI output myself.

### 3. My plan

**Next year:** strengthen my fundamentals in backend development and testing, and build one project that uses an AI API inside the product, with real evaluation (test sets, accuracy, bias checks). **In five years:** work as an AI or ML engineer who builds AI features responsibly, with measurable quality, privacy protection and clear accountability.
